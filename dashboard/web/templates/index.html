How the agent works

Glitch Hunter is a game tester with no human at the controls. A trained agent plays Super Mario Bros Level 1-1 while the dashboard watches the game for bugs. One test step, over and over:

  1. See

    The agent looks at the game screen: the last 4 frames, made small and grey.

  2. Play

    It presses one of its 10 button moves, and the game runs 4 frames with it.

  3. Check

    Its rules check every frame: no passing through solid blocks, no invisible walls, no hits without contact, no impossible jumps.

  4. Report

    A broken rule stops the test. The frame, a GIF and a replay check are saved, and a report says where to fix the bug.

      2How the agent tests each game

      Start testing

      The agent loads the chosen game and starts a run from the beginning of the level.

      Play one step

      See the last 4 frames, pick a move, the game runs 4 frames. Each run takes a new route: the agent draws its moves from what it learned.

      Check every frame

      Its rules, judged against what is drawn on screen.

      A rule broken?

      No: keep playing. Yes: a bug.

      Clean game

      No rule should break

      The original game. Any bug report here would be a false alarm.

      Mario reaches the castle

      Or he dies, or gets stuck: a stuck run is ended after about 13 seconds without progress.

      Testing stops

      The game screen holds the last frame, with LEVEL COMPLETE in its corner.

      No Bugs Found report

      A PDF, Markdown, the final frame and a GIF, saved and listed in Bug History.

      Bugged game

      A planted bug is met

      Each run takes its own route, so it meets its own set of the planted bugs.

      Testing stops at that frame

      The game screen holds the frame, with BUG FOUND in its corner.

      Evidence, replay, report

      The frame, a GIF and the run are saved; a separate replay proves the bug happens again; PDF and Markdown reports say where to fix it.

      Resume testing

      The run carries on from the same moment and stops again at the next bug, or at the castle.

      What the status colours mean

      • Testing The agent is playing and every frame is being checked.
      • Paused Stopped by you; nothing is lost and Resume continues.
      • Bug found A rule broke; testing stopped by itself and the evidence is saved.
      • No bugs found A clean run reached the castle and no rule broke.
      • Warning Something needs attention: a fallback agent, a lost connection, a failed step.

      5The clean game and the bugged game

      Live Testing can run the same level in two versions. You choose one with the game switch before pressing Start Testing.

      Clean game

      The original level, exactly as it ships. Its files are locked by a fingerprint, so nothing in it can be changed by accident.

      What it is for: watching the agent play, and proving the checks stay quiet. It has no bugs, so any report here would be a false alarm. Reaching the castle ends the run with a No Bugs Found report. Every agent was trained and measured on this game.

      Bugged game

      An exact copy of the level with known bugs planted on purpose. Each one is declared in a list and marked in the code.

      What it is for: proving the checks find real bugs. The agent takes its own route each run and meets some of them; each one it meets stops the run with saved evidence and a report. The checks are general rules and do not know where any bug is.

      • 1 Walk Right
      • 2 Walk Right + Jump
      • 3 Run Right

      • 5 Jump
      • 6 Walk Left
      • 7 Crouch
      • 8 Run Left (momentum retreat)
      • 9 Left + Jump
